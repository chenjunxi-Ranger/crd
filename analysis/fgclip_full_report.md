# FG-CLIP 全量评测（基座层，纯余弦）

> 2026-11-05。实现：`scripts/backbone_full.py`；产物 `results/gate/fg_full_*.json`、`fg_scores_*.npz`。
> 两基座评的是**完全相同的 val 行**；CI 为按 image_id 聚类的 bootstrap（1,000 次）。

## 1. 结果

| bench | n | CLIP B/32 | FG-CLIP B/16 | Δ | FG-CLIP 95% CI | 门槛 | 判定 |
|---|---:|---:|---:|---:|---|---:|---|
| COCO | 5,000 | 0.9287 | **0.9642** | **+3.55** | [0.9593, 0.9689] | 0.960 | 点估计过，CI 下界差 0.0007 |
| Flickr | 1,014 | 0.9505 | **0.9768** | **+2.63** | [0.9663, 0.9854] | 0.960 | **CI 下界过线** ✅ |
| MM-IMDb | 2,608 | 0.8340 | **0.8565** | **+2.25** | [0.8419, 0.8711] | 0.880 | 未过，差 2.35 |
| FOIL | 10,000 对 | 0.8997 | **0.9131** | **+1.34** | [0.9060, 0.9198] | 0.920 | 未过，差 0.69 |

## 2. 与子集结果的区别（重要）

之前 1,500 行子集给出的 MM-IMDb 是 0.8342，全量只有 **0.8565**；
子集与全量的差距说明**子集上的增益偏高**，必须以全量为准。COCO 同理（子集 0.9577 → 全量 0.9642，方向相反但幅度不同）。

## 3. 判读

1. **基座贡献确实存在且不小**：+1.3 到 +3.6 点，四列方向一致。
2. **但它是基座贡献，不是方法贡献**。这两部分必须在论文里分开报，
   方法部分要用 `Δ_method = AUC(FG-CLIP + Ours) − AUC(FG-CLIP + 基线)` 单独度量。
3. **COCO / Flickr 已经靠纯余弦接近或达到门槛**，这意味着方法若只在这两列上"提升"，
   很容易被质疑是基座功劳；**方法的价值必须体现在 MM-IMDb（差 2.35）与 FOIL（差 0.69）上**。
4. MM-IMDb 的 +2.25 也说明：即使换到细粒度基座，该列的瓶颈依旧——与之前"文本被截断"的判断一致。

## 4. 局部特征接口现状

| 接口 | 可用性 |
|---|---|
| `get_image_features` → (B,512) | ✅ |
| `get_image_dense_features` → (B,196,512)，14×14 patch | ✅ |
| `get_image_box_roi_features(box_info=...)` | ✅（需自备框） |
| `get_text_features(..., use_bbox, walk_short_pos)` | ✅ 池化 |
| token 级文本特征 | ⚠️ 自定义 `text_model.forward` 需要额外参数（`mask1` 等），
直接调用会报 shape 错，需要按其实现传参或读 `last_hidden_state` 的等价出口 |

因此"局部语义证据"这套方法**在图像侧已经具备条件**，文本侧还需要一次接口适配。
