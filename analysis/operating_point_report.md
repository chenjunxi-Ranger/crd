# 操作点审计：余弦 vs A（同一 FPR）

> 2026-11-05。实现：`scripts/operating_point_audit.py`；产物：`results/bench/operating_point.json`。
> 阈值只在 val 的一半上选（clean 分位数），在另一半上评估，双向平均；三种子。

## 0. 先更正上一份归因表的阈值口径

上一份 FP/FN 表用的是**对 cosine 和 A 各自在同一批 val 上选 best-F1 阈值**。
两者量纲与分布不同，等于用两个不同的操作点比较混淆矩阵——
所以"密度项造成 983 个 FP"这个读数不可直接解读。本报告用固定 FPR 修正。

## 2. 三条结论

1. **"983 个 FP" 是阈值校准的产物**：在同一 FPR 下，A 的 FP 数与余弦几乎相同（MM-IMDb 1% 处 54 vs 53），
   但 TPR 从 0.108 升到 0.209。A 不是"用更多误报换召回"，而是在同等误报下召回更高。
2. **MM-IMDb 的真正问题不是"校正破坏排序"，而是绝对可分性低**：
   即使在 10% FPR 下，A 也只能召回 63.2%；余弦只有 45.6%。这一列是结构性困难。
3. **COCO / Flickr 上 A 全面优于余弦**（+1.3 到 +9.5 点），没有"某档退化"的迹象。

## 3. 对研究方向的修正

- 上一轮"MM-IMDb 的密度校正引入大量 FP"这一说法**撤回**；
- 但"MM-IMDb 与 COCO/Flickr 的错误结构不同"仍然成立——只是差异不在校准，而在
  **余弦本身的可分性**（MM-IMDb 的余弦 TPR@1% 只有 0.108）。
- 因此 MM-IMDb 需要的不是"调整阈值"，而是它自己的语义证据（文本是被截断的剧情简介）。
