# 四数据集任务构造与标签语义审计

> 2026-11-05。实现：`scripts/task_audit.py`；产物 `results/bench/task_audit.json`。
> 直接读派生 CSV 与生成列（`donor_image_id` / `donor_sentence` / `cat_labels`），未重新标注。

## 1. 基本构造

| 项 | COCO | Flickr | MM-IMDb |
|---|---:|---:|---:|
| 总行数 | 123,287 | 31,014 | 25,959 |
| 划分 | 113,287 / 5,000 / 5,000 | 29,000 / 1,014 / 1,000 | 15,552 / 2,608 / 7,799 |
| 噪声率 | 0.400 | 0.389 | 0.400 |
| 同图 donor 率 | **0.000** | **0.000** | **0.000** |
| donor 是否在文件内 | — | — | **1.000** |

**结论 1**：COCO/Flickr 的负样本一律来自**另一张图**（provenance mismatch），
但 donor 描述可能恰好也描述当前图 → 这就是人工标注中"noisy 被判 match"的来源。

## 2. MM-IMDb 的负样本构造（本轮最重要的发现）

| 检查 | 结果 |
|---|---|
| noisy 行的 `sentence` 与 `donor_sentence` 是否相同 | **1.000**（完全一致） |
| donor 电影是否与目标电影共享至少一个类型 | **1.000（100%）** |
| donor 与目标类型集合完全相同 | 0.082（8.2%） |
| 平均类型数 | 2.50 |

也就是说：**MM-IMDb 的负样本是"同类型另一部电影的剧情简介"**贴在当前海报上。

**结论 2**：这一列考验的是"这段简介是不是这部电影的"，而不是"简介里的每个事实能否在海报上找到视觉证据"。
由于 donor 已经做过类型匹配，任何**类型级**视觉线索（色调、题材、海报风格）都被中和，
剩下的判别信息是**具体影片身份**——而海报上通常不可见。

**这解释了为什么**：
- MM-IMDb 换基座只涨 2.25 点（信息不在视觉侧）；
- 局部 patch 证据在该列是负增量（它衡量的是"短语能否找到视觉区域"，与"是不是这部电影"无关）；
- 人工标注在困难组没有发现语义富集（因为困难样本的语义本来就成立，只是不属于这部电影）。

## 3. 四列的任务语义对照

| 维度 | COCO | Flickr | FOIL | MM-IMDb |
|---|---|---|---|---|
| 原始配对 | 图像—描述 | 图像—描述 | 图像—描述 | 海报—剧情简介 |
| 负样本 | 跨图 donor（0% 同图） | 跨图 donor | 同图反事实替换 | 跨电影 donor，**100% 同类型** |
| 检测目标 | 来源错配 ∩ 语义错配 | 同左 | **纯语义矛盾** | **影片身份关联** |
| 局部视觉可验证性 | 高 | 高 | 高（细粒度） | **低** |
| 标签语义是否可能重叠 | 是 | 是 | 较少 | 是（类型一致但影片不同） |

## 4. 对方法设计的直接含义

1. 四个 benchmark **不是同一个任务**：两个是"来源错配"，一个是"语义矛盾"，一个是"影片身份"。
   用单一评分公式同时最优，本身缺乏先验保证。
2. 之前所有候选（VES / CDUS / BCSC / 局部证据）都在做"视觉可验证性"，
   而这恰好只覆盖前三列、对第四列无效。
3. 若论文要继续，必须明确**要检测哪一种关系**，并给出与该关系匹配的证据定义；
   而不是用一个名字（"图文错配"）统摄三种关系。
