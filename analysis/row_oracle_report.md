# 逐样本 Oracle 可分解性审计

> 2026-11-04。实现：`scripts/row_oracle_audit.py`；产物：`results/gate/row_oracle_audit.json`。
> $u_i=\frac1{N_{\bar y}}\sum_{j:y_j\ne y_i}\delta_{ij}$，$\delta_{ij}=\mathbb I(\text{CSLS}_{ij}\text{对})-\mathbb I(\text{CLIP}_{ij}\text{对})$。

## 1. 逐记录净收益与稳定性

| bench | u 均值 | u>0 占比 | u<0 占比 | u=0 | **五折符号全一致** | 记录间方差 | 记录内方差 |
|---|---:|---:|---:|---:|---:|---:|---:|
| COCO | +0.0065 | 47.6% | 28.3% | 24.1% | **0.348** | 4.25e-3 | 2.64e-4 |
| Flickr | +0.0036 | 47.4% | 25.1% | 27.4% | **0.149** | 1.12e-3 | 1.65e-4 |
| MM-IMDb | +0.0082 | 44.3% | 43.4% | 12.3% | **0.513** | 6.17e-3 | 3.68e-4 |

**第一道门槛未通过**：一条记录的 CSLS 净收益，换一批比较对象后符号就变。
COCO 只有 34.8% 的记录五折同号，Flickr 只有 14.9%。

记录内方差虽小（2.6e-4），但那是相对于同样很小的 |u| 而言；当均值只有 0.006 时，
符号本身几乎由噪声决定。

## 2. 无标签特征能否解释 u

Spearman ρ（clean / noisy）：

| 特征 | COCO | Flickr | MM-IMDb | 方向一致性 |
|---|---|---|---|---|
| s（CLIP 分数） | −0.62 / −0.68 | −0.51 / −0.55 | −0.48 / −0.49 | ✅ 四列同向 |
| h（库侧支撑） | −0.77 / −0.61 | −0.83 / −0.44 | −0.83 / −0.91 | ✅ |
| r_I | −0.65 / −0.49 | −0.64 / −0.32 | −0.46 / −0.51 | ✅ |
| r_c | −0.61 / −0.39 | −0.63 / −0.30 | −0.70 / −0.77 | ✅ |
| 图像 max 边际 | +0.27 / +0.54 | +0.19 / +0.44 | +0.34 / +0.29 | ✅ |
| 文本 max 边际 | +0.26 / +0.57 | +0.21 / +0.43 | +0.15 / +0.12 | ✅ |

**第二道门槛部分通过**：存在方向一致的无标签代理（低 s、低 h、大边际 → CSLS 更有利）。
但这些量恰好就是 CSLS 分数本身已经使用的那些，把它们再包成门控，等于对同一个量做二次变换。

## 3. 三处口径修正

| 项 | 原报告 | 修正后 |
|---|---|---|
| "都错" | 3.84% / 2.68% / 14.33% | 这是 **CLIP 与 CSLS 同时错**；四候选全错为 **0.92% / 0.78% / 4.96%** |
| 分档可加性 | 0.0291 vs 0.0290 | 用未四舍五入值重算，误差 **1e-16**，完全可加 |
| 基线口径 | 0.9295 / 0.8253 | 1200 行审计子集为 0.9266 / 0.8075；**C5 判定必须用全量 val/test**，审计数字不能混用 |

## 4. 结论

1. **pairwise Oracle 的优势无法稳定分解到单条记录**——符号一致性 0.15–0.51，远未达到可门控的水平。
2. 因此"逐样本门控"这条路，在纯库侧 CSLS 上**不成立**，不是公式不够复杂。
3. 与此同时，CSLS 在全局已经是净正贡献（净纠错 +9.9k/+2.6k/+11.5k），
   **最优的可部署规则就是不加门控、统一使用 CSLS**（$\lambda=0.5$）。
4. 统一使用 CSLS 后：COCO 0.9556（差 0.44）、Flickr 0.9691（过）、
   MM-IMDb 0.8415（差 3.85）、FOIL 0.917（差 0.3）。

**这一轮把"决策规则"这条路也走到了终点。**
剩下的 0.44 pp（COCO）与 3.85 pp（MM-IMDb）不是选择问题，而是表示问题。
