## 1. 训练对审计（你要求的第一个检查）

| 来源 | 对数 | 同图 | 跨图 |
|---|---:|---:|---:|
| FOIL 反事实 | 800 | **800** | 0 |
| COCO 困难负 | 400 | 0 | 400 |
| Flickr 困难负 | 200 | 0 | 200 |
| MM-IMDb 困难负 | 200 | 0 | 200 |
| **合计** | **1,600** | **50%** | **50%** |

- $\Delta r_I=0$ 的比例 = 50%（正好是 FOIL 那一半）；
- $\Delta r_c\neq0$ 的比例 = 100%；
- 两成员使用同一参考库。

**结论：不是 bug，而是协议对齐的必然。** FOIL 在推理时 $r_I$ 也抵消，
所以训练时不更新图像侧项是对的；图像侧项从跨图那一半获得梯度，覆盖行级所需。

## 4. 判定（对照你预先冻结的失败条件）

> "如果 B 仍然在 λ=0.8 下无法改善 FOIL，就不要再继续调 λ 或增加 LoRA 层数。"

**未通过，触发失败条件。**

ΔFOIL 的三组值（−0.0004 / 0.0000 / −0.0008）全部落在种子噪声（SD 0.0034）之内，
方向也不一致；三列行级完全持平。

## 5. 为什么目标对齐没有效果

1. 在同图对（FOIL）上 $m^+-m^-=(s^+-s^-)-0.8(r_c^+-r_c^-)$，$r_c$ 的差在数值上远小于
   余弦差（余弦跨度约 0.07，$r_c$ 项乘 0.8 后约 0.005），排序损失几乎等价于余弦排序；
2. 损失里还有 in-batch 对比项与锚束（权重 5.0），它们主导了优化方向；
3. 因此 300 步、lr=1e-4 下 A/B 收敛到几乎同一点（adapter 最大差 0.01）。

**结论：FOIL 的 3.2 点缺口不是"训练与推理目标不一致"造成的，而是当前表示与损失本身的能力边界。**
