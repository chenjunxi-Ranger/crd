# TRACED 机制复现（离线、机制级）

> 2026-11-05。实现：`scripts/traced_repro.py`。
> **限制**：环境无网络，无法 clone 官方仓库，因此这是按论文描述的**机制复现**，
> 不是逐位对齐的移植；数字不能与论文报告的 Accuracy 提升直接比较。

## 1. 复现的机制

```
c_0 --删词--> c_1 --删词--> c_2 --删词--> c_3        (每步贪心取分数最高的删除)
特征：s_final, 总增益, 每步增益(4 槽), 有增益的步数, 平均增益, 1 - 词重叠率
分类器：LogisticRegression（仅在官方 train 上拟合）
```

每样本调用预算：1 + 3×|候选词| ≈ 25 次（满足 M5 ≤40）。

## 2. 结果（CLIP ViT-B/32，官方 train 拟合、val 评估）

| bench | 训练/验证 | Cosine | TRACED 复现 | Δ |
|---|---|---:|---:|---:|
| COCO | 600 / 600 | 0.9349 | **0.9376** | **+0.27 pp** |
| MM-IMDb | 600 / 600 | 0.7985 | **0.8073** | **+0.89 pp** |

## 3. 判读

1. **机制在我们数据上是有效的**：两列均为正，且 MM-IMDb（最难的一列）增益更大（+0.89 pp）。
   这与 TRACED 的设计意图一致——"错误 caption 有更大的可改进空间"。
2. **量级与论文一致**：论文报告 Accuracy +2.4~2.8%，我们得到 AUROC +0.27~0.89 pp。
   两者指标不同、数据不同，只能说明"存在同量级的小幅增益"，不能说明我们复现了他们的数字。
3. **成本可接受**：约 25 次评分/样本，比 CSLS（离线建库）贵，但远低于任何生成式方法。

## 4. 尚未回答（下一阶段的核心）

- **与 CSLS 的关系**：轨迹特征与库侧密度是否重叠？若重叠，它就不是新证据；
- **在语义兼容 donor 上的表现**：我们的假设是"轨迹能揭示细粒度可改进性"，而这正是
  FG-CLIP 在兼容组上显示出优势的地方，两者是否指向同一批样本？
- **路径一致性**：当前只跑了一条贪心路径。多路径（不同删除顺序/替换）之间的一致性
  是候选新机制的核心，也是与 TRACED 单一路径的差别所在。

## 5. 下一步（按三阶段）

1. 把轨迹特征与 CSLS 做嵌套对照（cos / +CSLS / +轨迹 / +两者），确认是否有独立增量；
2. 在已标注的兼容组 40 条上比较"轨迹增益"与"FG-CLIP 增益"是否命中同一批样本；
3. 若 1 显示正增量、2 显示与 FG-CLIP 互补，则实现多路径一致性版本。
