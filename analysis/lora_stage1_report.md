# C3 修订后的 Stage 1：CLIP LoRA 适配

> 2026-11-04。实现：`scripts/lora_stage1.py`；产物：`results/gate/lora_*.json`。
> 只更新两个塔最后两个 block 的 `q_proj` / `v_proj`（rank 4），其余全部冻结；
> 训练集 = FOIL train（排除 val 图像）800 对 + COCO 400 + Flickr 200 + MM-IMDb 200（跨图困难负，冻结 CLIP 挖）。

## 1. 结果（600 行 / 600 对评测子集，纯余弦，无 CSLS）

| 配置 | COCO | Flickr | MM-IMDb | FOIL | 说明 |
|---|---:|---:|---:|---:|---|
| M0 冻结 CLIP | 0.9349 | 0.9532 | 0.7985 | 0.880 | 基线 |
| 排序损失（无 NCE，lr 1e-4，锚 5） | 0.8413 | 0.8651 | 0.7806 | 0.910 | 行级崩 9 点 |
| **排序 + in-batch 对比（NCE=1）** | **0.9305** | **0.9488** | 0.7711 | **0.920** | 行级基本保住 |
| 排序损失（lr 1e-3，800 步） | 0.5392 | 0.4554 | 0.5070 | 0.757 | **完全塌陷** |

## 2. 三个可用的结论

1. **C3 放宽确有作用**：在唯一保住行级的配置里，FOIL 从 **0.880 → 0.920（+4.0）**，
   而行级只掉 0.4 / 0.4 点。这是本项目第一次在不摧毁行级的前提下把 FOIL 推过门槛。
2. **冲突仍在，但形态变了**：只加排序损失时，模型把空间拉向"词级反事实"，
   行级掉 9 点；加入 in-batch 对比项后两边基本平衡。也就是说冲突是**可以被一项显式的
   行级目标缓解的**，不再是权重层面的死结。
3. **MM-IMDb 是唯一持续恶化的列**（0.7985 → 0.7711，−2.7），与它 14.3% 的"双错"率一致：
   该列的瓶颈不在排序目标，而在文本表示本身。

## 3. 训练稳定性警告

lr=1e-3、800 步那次所有列塌到 0.4–0.5（排序损失有退化解：把所有向量挤到一起也能满足
`sp > sn`）。这说明该路线**必须**配强锚束 + 低学习率 + 显式行级项，否则会得到假增益。

## 4. 这些数字能说什么、不能说什么

- 能说：表示适配能在保持行级的同时把 FOIL 抬过门槛；
- 不能说：四列同时达标。当前 MM-IMDb 下降、COCO/Flickr 未测 CSLS、
  且评测只在 600 行子集上做了一次，没有种子方差。
