# C-VRR 预实验报告（FOIL val，2,000 对）

> 执行日期：2026-11-04。实现：`scripts/cvr_pre.py`；产物：`results/gate/cvr_pre.json`、
> `results/gate/cvr_scores_adjacent.csv`。
> 语料：FOIL 官方 train **排除 val 图像**（图像互斥，与 C6 一致）。
> 常数：候选上限 12、只干预"被替换的那个词"（FOIL 原生定位），CLIP 全程冻结。

## 1. 四项预实验

| 预实验 | 指标 | 相邻词上下文 | 内容词上下文 | 判据 |
|---|---|---:|---:|---|
| 1 覆盖率 | 负句该位置有候选 | 73.0% | 50.0% | — |
| 1 覆盖率 | **正确词进入负句候选集** | **43.7%** | **22.5%** | 需接近 100% 才能修 |
| 1 覆盖率 | 平均候选数 | 8.19 | 3.85 | — |
| 2 修复方向 | `R(I,c⁻) > R(I,c⁺)` 准确率 | 0.775 | 0.669 | 需 > CLIP |
| 3 互补性 | CLIP 错→修复对（纠正数） | **0 / 533** | **0 / 996** | 需 > 0 |
| 3 互补性 | CLIP 对→修复错 | 533 | 996 | — |
| 3 互补性 | 两者都对 / 都错 | 1234 / 233 | 771 / 233 | — |
| 4 消融 | CLIP 原始 | 0.8835 | 0.8835 | 基线 |
| 4 消融 | 修复遗憾单独 | 0.775 | 0.669 | 低于基线 |

λ 融合：`A = -s + λR` 在 λ ∈ {0, 0.5, 1, 2, 5, 10, 50, 200, 1e5} 上**准确率恒为 0.8835**，
即修复项对最终判定没有任何影响。

## 2. 机制诊断（为什么恒为 0.8835）

对 2,000 对逐对检查"修复方向与余弦方向是否冲突"：

- 名义冲突 533 对；
- **真实冲突 0 对**——这 533 对的 `R(I,c⁺)` 与 `R(I,c⁻)` 精确相等（两边都为 0，即该位置在语料中没有可用候选）。

也就是说：**只要修复遗憾真的非零，它的方向就与余弦方向一致**（两者相关 0.69）。
修复遗憾不是一个新证据源，而是余弦边际的一个更嘈杂的单调代理：

1. 正确词缺失时（56.3%），机制沉默；
2. 正确词存在时，替换带来的提升方向与"原句已经更好"同向，无法纠正 CLIP 的错误；
3. 因此 `union = CLIP`，λ 取任何值都不改变判定。

这与"候选集合太弱"和"上下文定义"都无关：内容词上下文覆盖率更低（22.5%），方向准确率也更差（0.669）。

## 3. 判据与结论

按你设定的门槛（覆盖率、方向、互补性、消融四项都要过）：

| 项 | 结果 | 判定 |
|---|---|---|
| 候选覆盖率 | 正确词仅 43.7% 可被提出 | ❌ |
| 修复方向 | 0.775 < CLIP 0.8835 | ❌ |
| 互补性 | 纠正 0 例 | ❌ |
| 消融 | 语料结构未显示增益（内容词更差） | ❌ |

**结论：C-VRR 预实验未通过，不进入五阶段正式迭代。**

## 4. 如果还要救这个方向

需要改变的是"修复遗憾"的定义，而不是调 λ：

1. **候选生成不能只靠双侧 bigram**：正确词缺失 56%，说明语料桥接太窄；可换成"同名词类/同 dependency 位置"的候选，但这会引入新的解析器（新的非 CLIP 组件）。
2. **遗憾必须能反对余弦**：当前 `max_u s(c←u)` 的提升天然与余弦同向。若要产生反向证据，需要比较"替换后的 *相对* 排名"（而非绝对分数），例如替换前后该图在库中的排名变化——但那又回到库侧归一化。
3. **只干预一个词**是 FOIL 的便利假设；真实错标（整句换图）没有单一编辑点，机制无法定位。

在现有约束（单公式、单常数、冻结 CLIP）下，上述三点都会把方法推回已经测过的算子族
（库侧秩、语言先验、局部对齐），因此本轮不建议继续投入。
